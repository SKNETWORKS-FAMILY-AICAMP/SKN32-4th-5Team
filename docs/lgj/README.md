## 흡수 결과 — 배포계획서가 바꾼 것

**`docs/12 §6` 이 *목표* 에서 *실물* 이 됐다.** 오래 그림으로만 있던 절인데, 배포가
실제로 끝난 것이 이 문서로 확인됐다 (`pettriage.kro.kr` · ACM Issued · ALB ·
EC2 `m7i-flex.large`). 예전 그림은 **다섯 군데가 실물과 달라서** 통째로 고쳤다 —
무엇이 달랐는지는 `docs/12 §6.2` 에 표로 남겼다.

**`docs/12 §10` 의 미결 둘이 닫혔다** — TLS(→ ACM + ALB) · 미디어 위치(→ EBS, S3 미사용).

**`docs/12 §6.3` 에 배포에서만 나오는 함정 둘을 남겼다.** 특히
*"`proxy_params` 중복 사용 금지 — 400 오류 원인"* 은 실제로 겪지 않으면 안 나오는 한 줄이다.

**D-107 이 나왔다** — 운영은 systemd, `compose.yaml` 은 로컬 개발용으로 역할을 좁힌다.

## 🔴 배포계획서에 남은 정정 · 미결 넷

**① 문서 안에서 Docker 와 systemd 가 갈린다.** §3·§4 는 전부 EC2 systemd 서비스인데,
§9 배포 완료 기준은 *"…**컨테이너**가 모두 정상 기동한다"* 이고 §8 은
*"Docker 이미지 태그로 롤백"* 이다. **실물이 systemd 이므로 §8·§9 를 고쳐야 한다** (D-107).

**② `migrate` 대상이 모자란다.** 절차 7번이 `migrate auth sessions contenttypes admin`
인데 **`pets` · `diary` 가 없다.** D-104 가 그 스키마의 주인을 Django 로 정했다.
배포 서버에서 그 표가 어떻게 생겼는지 확인이 필요하다.

**③ 설치 그룹이 모자란다.** 절차 6번이 `pip install -e .[django,db]` 인데
**`[rag]` · `[ingest]` 가 없다.** 그대로면 Chroma·LangGraph 가 없어 AI 응답이 못 나와야
하는데 V-03 은 도달한다고 적혀 있다. 실물이 문서보다 많이 깔린 상태일 것이다.

**④ §7 검증 결과표가 비어 있다.** 결과 칸 4개와 캡처 4장이 빈 자리다.
**배포는 했는데 증거가 아직 안 붙었다.** `docs/ksr` 의 `TC-NFR-DEPLOY-*` 미실행 15건과
**같은 칸**이라, 한 번 재면 두 문서가 같이 채워진다.

## 🔴 `deploy/` 가 없다 — 지금 이 배포는 재현할 수 없다

EC2 의 `nginx.conf` 와 systemd unit 파일이 **git 에 없다.** 저장소의
`docker/nginx/nginx.conf` 는 Docker 용이고 다른 물건이다.

**그 기계가 죽으면 아무도 같은 것을 다시 세우지 못한다.** D-107 ①이 이것을
`deploy/` 로 가져오는 일이고, 배포계획서에서 나온 항목 중 **가장 급하다.**
