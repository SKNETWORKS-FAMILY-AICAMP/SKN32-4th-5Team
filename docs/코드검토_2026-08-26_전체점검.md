## A. 🔴 채팅 내역 화면이 지금 깨져 있다

### 증상

`/history/` · `/history/<session_id>/` 가 `OperationalError: no such table: chat_sessions` 로 죽는다.

### 근거

```python
# chat/models.py
class ChatSession(models.Model):
    class Meta:
        managed = False              # Django 가 이 표를 만들지 않는다
        db_table = 'chat_sessions'
```

```
$ webapp.sqlite3 의 표
auth_group · auth_permission · auth_user · … · diary_entries · pets · django_session
→ chat_sessions 없음 · chat_messages 없음
```

`chat/views.py:22` 의 `session_list` 가 `ChatSession.objects.filter(...)` 를 부른다.

### 왜 이렇게 됐나 — **두 결정이 서로를 모른다**

| 결정 | 내용 |
|---|---|
| `chat/models.py` (lgj) | `managed=False` — *"Django 는 읽기만 한다"* |
| **D-104** (2026-08-26) | 웹앱 DB 와 3차 DB 를 **분리**한다 |

`managed=False` 는 *"표가 이 DB 에 이미 있다"* 를 전제한다. 그런데 D-104 가 DB 를 갈라
놓으면서 **그 표는 다른 DB 에 남았다.** 게다가 데이터를 쓰는 쪽은 FastAPI 의
`chat_logger` 라, 표를 옮겨도 **쓰는 곳과 읽는 곳이 다른 DB** 다.

> 🔴 **`managed=False` 자체는 옳은 선택이었다.** 무너진 것은 그 전제다.
> 결정 하나가 다른 결정의 전제를 조용히 무너뜨렸고, **테스트가 없어서 아무도 몰랐다.**

### 선택지

| 안 | 방법 | 대가 |
|---|---|---|
| **A-1** | 7b 에서 DB 를 합칠 때 자연히 풀린다. **그때까지 SC-09·SC-10 은 안 되는 것으로 둔다** | 발표에 채팅 내역을 못 넣는다 |
| **A-2** | 대화 적재를 Django 로 옮긴다 (`managed=True` + 마이그레이션 + `chat_logger` 이관) | 7b 작업을 앞당기는 것. 범위가 커진다 |
| A-3 | Django 다중 DB + 라우터로 3차 DB 를 함께 본다 | 설정이 복잡해지고 7b 에서 다시 걷어내야 한다 |

**A-1 또는 A-2 다.** A-3 은 곧 지울 것을 위해 구조를 늘린다.

## B. 🔴 사진 업로드에 관문이 없다

### 증거

```python
# pets/views.py:49
if request.FILES.get("photo"):
    pet.photo = request.FILES["photo"]      # 받은 것을 그대로 저장한다
```

검증도, 정규화도, 재인코딩도 없다. `webapp/settings.py` 에 업로드 크기·형식 제한 설정도 **0개**.

### 그런데 3차는 이 조건을 명시해 두었다

```python
# src/pettriage/app/routes/pets.py:42
D-43 사진은 아직 없다. 붙일 때 **관문 5단계를 통과한 것만** 저장한다.
```

**3차는 정직하게 "안 붙였다"고 적고 조건을 남겼다.** 4차가 사진을 붙이면서 그 조건을 지나쳤다.
`src/pettriage/privacy/` 는 `__init__.py` 뿐인 빈 모듈이다.

### 실제 위험

| 무엇 | 왜 문제인가 |
|---|---|
| **EXIF 가 그대로 남는다** | 스마트폰 사진에는 **GPS 좌표**가 실린다. 보호자의 집 위치가 서버에 남는다 |
| 원본 파일명이 남는다 | 파일명에 이름·날짜가 들어가는 일이 흔하다 |
| 형식·크기 제한이 없다 | 대용량 업로드로 디스크를 채울 수 있다 |

D-01 이 이 도메인을 고른 이유 중 하나가 *"개인정보 리스크가 낮다"* 였고,
D-36 이 *"개인정보는 LLM 에 닿기 전에 코드가 벗긴다"* 로 정했다.
**사진은 LLM 에 안 가지만 디스크에는 남는다.**

### 최소 관문 (얼굴 검출 없이)

D-43 원안의 5단계 중 **얼굴 검출은 무겁다.** 나머지 넷만으로도 위 위험은 사라진다.

```
① 형식·크기 검증        허용 확장자 · 상한 (예: 5MB)
② Pillow 로 다시 연다    열리지 않으면 이미지가 아니다
③ 리사이즈 + 재인코딩    ← **EXIF 가 여기서 자동으로 사라진다**
④ UUID 파일명으로 저장   원본 파일명을 버린다
```

③이 핵심이다. `Image.open(...).convert("RGB").save(...)` 는 메타데이터를 옮기지 않는다.
Pillow 는 이미 의존성에 있다 (`django` extra).

## C. 🔴 배포 보안 설정이 하나도 없다

`webapp/settings.py` 에서 **6개 항목 모두 0건**이다.

```
SECURE_SSL_REDIRECT · SESSION_COOKIE_SECURE · CSRF_COOKIE_SECURE
SECURE_HSTS_SECONDS · X_FRAME_OPTIONS · CSRF_TRUSTED_ORIGINS
```

`DEBUG` 를 `false` 로 고친 것(2026-08-26)은 첫 단추일 뿐이다. HTTPS 로 배포하면서

### 도구가 이미 있다

```powershell
python manage.py check --deploy
```

Django 가 **빠진 항목을 전부 나열해 준다.** 9단계 배포 절차서에 이 명령을 넣고,
CI 에도 넣으면 사람이 기억할 필요가 없다.

## D. 🔴 `/api/ask` 는 무인증인데 nginx 가 공개한다

### 증거

```python
# src/pettriage/app/routes/ask.py:29
@router.post("/ask", response_model=AskResponse)
def ask(req, engine=Depends(get_engine), sessions=Depends(get_sessions), db=Depends(get_optional_db)):
```

인증 의존성이 없다. 그리고 —

```nginx
# docker/nginx/nginx.conf
location /api/ { proxy_pass http://fastapi; }     # /api/ask 가 여기로 간다
```

**인터넷에서 누구나 `POST /api/ask` 를 부를 수 있다.**

### 왜 지금까지 문제가 아니었나

3차는 로컬 시연이었다. 4차는 **AWS 에 올린다.**

| | |
|---|---|
| 질의 1건 | LLM 호출 **6~7회** (14 §1.3) |
| 속도 제한 | 없다 |
| 인증 | 없다 |

주소가 알려지면 **비용이 그대로 나간다.** 그리고 `12 §8` 이 *"8001 을 막는 것이 이 시스템에서
가장 중요한 한 줄"* 이라고 적었는데, **nginx 가 80 에서 대신 열어 준다.** 포트를 막아도
경로가 열려 있으면 같은 것이다.

### 선택지

| 안 | 방법 | 대가 |
|---|---|---|
| **D-1** | Django 세션 인증을 거치게 한다 | 🔴 워커 점유 — `12 §10` 의 그 문제 |
| **D-2** | nginx 에서 `/api/ask` 에 속도 제한(`limit_req`)을 건다 | 인증은 여전히 없다. 비용은 막힌다 |
| **D-3** | 발표 기간에만 IP 를 제한한다 | 시연에는 충분. 근본 해결은 아니다 |

**최소한 D-2 는 배포 전에 필요하다.** D-1 은 `12 §10` 의 미결과 같은 결정이다.

## E. ⚠️ DRF `BasicAuthentication` 이 켜져 있다

```python
# webapp/settings.py
"DEFAULT_AUTHENTICATION_CLASSES": [
    "rest_framework.authentication.SessionAuthentication",
    "rest_framework.authentication.BasicAuthentication",   # ← 필요 없다
],
```

주석이 *"임시 — JWT 냐 세션이냐는 미결"* 이라고 적혀 있는데, **그 미결은 D-104 로 닫혔다**
(세션 인증). Basic 인증은 브라우저 팝업 자격증명 경로를 열어 두는 것이고 우리는 쓰지 않는다.
**쓰지 않는 인증 방식은 공격면일 뿐이다.**
